# 2026-10-31

- GitHub の Flux image update auto-merge workflow が失敗する原因を GitHub Actions log で確認した。`gh pr merge --auto` は `main` に branch protection rule がないため GitHub GraphQL API に拒否されていた。PR workflow 成功後に、その workflow が検証した head SHA が現在の PR と一致する場合だけ squash merge するよう変更した。
- 既存の open image update PR はすべて `DIRTY` で、GitHub 上で競合していることを確認した。競合がある PR は GitHub が merge を拒否するため、競合解消後に workflow が成功してから merge される。
- `platform-config` の `wait: true` が ExternalSecret の Ready 状態を待ち、1Password 側の rate limit 等で `apps` Kustomization と image automation の開始を止め得ることを確認した。`wait: true` を削除し、secret provider の失敗をアプリ・image automation の reconcile gate にしない構成に変更した。
- Flux README に `platform-config` / `apps` の依存理由と secret provider を待たない方針を記載した。
- この実行環境では `kubectl` が見つからず、devcontainer 経由の cluster 状態確認は実施できなかった。変更の cluster 適用・実動作確認は未実施。
